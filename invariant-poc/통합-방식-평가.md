# 불변식 실행 방식: 1차 평가

> 이 문서는 초기 대안 검토 기록이다. 이후 Hypothesis 사용 목적에 따라 **Python Hypothesis + Java 테스트 어댑터 + GitHub Actions 실행**으로 결정했다. 현재 구현과 설정의 기준은 [README](README.md)이며, 아래 jqwik 추천과 실행 환경 제약은 당시 평가를 설명한다.

## 결론

현재 코드 구조에 가장 자연스럽게 들어가는 후보는 **Java/JUnit 기반 실행(jqwik 검토)**이다. 다만 실제 저장소에서 두 방식을 비교 실행한 결과는 없으므로 최종 결정이 아니라 다음 단계 기술 검증을 위한 추천이다. 기존 Hypothesis PoC의 반례 탐색·재생 방식도 유지하며 동일 시나리오로 비교한다.

| 항목 | Python/Hypothesis + HTTP | Java/JUnit + jqwik |
|---|---|---|
| 현재 러너와 연결 | Python 런타임과 드라이버, 앱 기동 방식 필요 | 현재 Gradle/Maven·JUnit 보고 경로와 더 가까움 |
| Java 내부 객체 접근 | HTTP 또는 별도 어댑터 필요 | 테스트 코드가 직접 접근 가능하나 프로젝트 구성에 의존 |
| DB 상태 초기화 | 양쪽 모두 fixture·독립 DB 및 인증 설계가 필요 | 양쪽 모두 fixture·독립 DB 및 인증 설계가 필요 |
| 대상 언어 확장 | HTTP 계약이 있다면 언어와 무관하게 접근 가능 | Java 중심 |
| 기존 PoC | 반례 탐색 및 구체 입력 재생의 메모리 fixture 확인 | 아직 실험하지 않음 |

현재 `runner/run-tests.sh`는 Gradle/Maven 테스트와 JUnit 결과 수집을 수행한다. `EvidenceService`는 생성한 Java 테스트를 러너에 전달한다. 따라서 Java 방식은 기존 실행 계약을 활용할 가능성이 있지만, 대상 프로젝트에 jqwik 의존성을 안전하게 제공하는 방법, Gradle/Maven과 JUnit 호환성, 테스트 격리 및 반례 전달은 새로 검증해야 한다. 기존 base/head 작업은 병렬이므로 어느 방식이든 head의 구체 반례를 base에 재생할 조정 단계가 추가로 필요하다.

## 다음 단계의 비교 시나리오

같은 샌드박스의 게시글 작성자 ID 보존 규칙과 의도된 회귀를 대상으로, 두 방식에서 독립 DB 초기화, 인증, 반례 발견·축소, 동일 입력 재현을 확인한다. 기동 시간·실행 시간·필요한 환경 변경·재현율을 기록한다. 현재 실행 환경에는 Java 21과 Docker/PostgreSQL이 준비되지 않아 통합 실측을 수행하지 못했다.

## 이번 단계의 PR별 설정

PR 상세 화면의 규칙 초안은 해당 PR에 저장되는 자유 텍스트다. 이 내용은 실행 가능한 규칙이나 승인된 테스트로 변환되지 않으며, 자동 실행·판정·후보 추출과 연결하지 않았다. 설정은 PR 단위로 유지되며 이후 같은 PR의 새 커밋에서도 유지된다.
