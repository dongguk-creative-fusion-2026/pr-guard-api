# 실행 연결 검증 결과

검증일: 2026-10-31. 로컬 기능 브랜치 기준.

## GitHub Actions 전환

리팩토링 후 Java 21 테스트 **125개**, Python 테스트 **9개**, 웹 프로덕션 빌드와 actionlint가 통과했다. 실행 조정(`InvariantExecutionService`), 저장(`InvariantRunRepository`), 결과 검증(`InvariantResultReader`)을 분리하고 실제로 관측한 회귀 JSON의 판정이 유지되는지 확인했다. 프런트의 타입·폴링 훅·결과 표시도 분리했다.

현재 구현은 API가 Actions를 요청하고 artifact를 수집하는 방식이다. 아래 Docker 검증 기록은 이전 구현의 이력이며 현재 실행 요구 사항이 아니다. 해당 Docker 실행 코드와 러너 Dockerfile은 제거했다.

- Actions용 동일 러너를 컨테이너 없이 직접 실행해 실제 Spring/JPA/Hypothesis 회귀 탐지와 base/head 재현을 확인했다.
- `actionlint`로 새 워크플로 문법과 표현식을 검사했다.
- API의 Actions 요청, 실행 UUID·브랜치·차수 바인딩, artifact 경로·크기·커밋 검증, 상태 분류, 타임아웃에 대한 Java 테스트를 추가했다.
- 웹은 Actions의 QUEUED/RUNNING 상태와 실행 링크를 표시하며 프로덕션 빌드를 확인했다.
- 새 워크플로의 실제 GitHub 호스팅 실행은 기본 브랜치 반영 후 확인해야 한다. 배포·자동 활성화는 수행하지 않았다.
- 이번 전환의 API/PostgreSQL 통합 테스트는 로컬 DB가 중지되어 실행하지 못했다. 모의 Actions API 테스트 도구는 컨테이너 명령 없이 재작성했다.

## 확인한 동작

- Python 빠른 테스트 9개 통과: 신규·기존 위반, 재현 불일치, 잘못된 요청, 알 수 없는 후보 거부, DB 생성 ID 차이 처리.
- Java 백엔드 테스트 117개 통과: Java 21, 영문 임시 경로. 작업 폴더의 한글 경로에서는 Gradle 테스트 클래스 로딩 문제가 있어 임시 복사본에서 실행했다.
- Next.js 프로덕션 빌드 통과.
- 실제 Docker/Spring/JPA/Hypothesis 통합 테스트 통과. 샌드박스의 임시 복제본에만 회귀를 심었고 원본은 변경하지 않았다.
- 모의 LLM HTTP 응답 → 규칙 후보 → 실제 PR #24 코드의 Docker/Hypothesis 실행 → PostgreSQL 결과 저장 → 조회 API 경로 통과.
- 존재하지 않는 실행 이미지에 대한 전체 API 테스트 통과: FAILED / execution_error로 저장하며 규칙 통과로 처리하지 않음.

## 실제 회귀 탐지 결과

규칙: 게시글 수정 전후 작성자 ID 유지.

```json
{
  "status": "new_violation",
  "input": {"title": "0", "content": "0"},
  "base": [
    {"author_before": 1, "author_after": 1},
    {"author_before": 3, "author_after": 3}
  ],
  "head": [
    {"author_before": 173, "author_after": 174},
    {"author_before": 175, "author_after": 176}
  ]
}
```

실행은 실제 `PostService.update`와 JPA를 사용했다. 각 예제의 트랜잭션을 rollback하므로 생성 ID 자체는 증가할 수 있으며, 같은 고정 데이터 관계를 만들어 작성자 보존 여부를 비교한다.

정상 PR #24 (`985c949093c6a51065a2cb98f922ce20464600dd`)에서는 head의 100개 탐색 예산에서 반례 미발견으로 종료했다. 이는 전체 입력에 대한 증명이 아니며 이 경우 base 재생은 하지 않는다.

## 범위와 남은 검증

- 현재 실행 가능한 어댑터는 pr-guard-sandbox의 작성자 ID 보존 규칙 하나다. 다른 업무 규칙은 해석 후보만 제공한다.
- 실행 대상 DB는 H2 PostgreSQL 호환 모드다. 실제 PostgreSQL 고유 동작과 HTTP 인증 경로는 검증하지 않았다. 결과 저장 DB는 실제 PostgreSQL이다.
- 전체 API 테스트에서 LLM HTTP 응답은 모의 서버를 사용했다. 실제 모델의 의미 해석 정확도 및 비용 평가는 수행하지 않았다.
- 브라우저에서 실제 버튼을 누르는 UI 종단 간 테스트는 수행하지 않았다. UI의 빌드·타입 검사와 실제 백엔드 API 경로를 각각 확인했다.
- 로컬 단일 인스턴스, 수동 실행, 관찰 모드이다. 결과는 머지 판정에 반영하지 않는다.
